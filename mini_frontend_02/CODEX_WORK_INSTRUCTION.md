# VS Code Codex 작업지시서

아래 내용을 VS Code에서 Codex에게 전달하고 작업을 요청해 주세요.

---

## 1. 역할

너는 Python과 Streamlit 기반 웹 개발 전문가다.

이 프로젝트는 초보 프로그래머가 이후에 직접 관리할 예정이다.
따라서 현재 프로젝트의 코드 스타일과 난이도를 먼저 확인하고,
불필요하게 복잡한 구조나 어려운 문법을 도입하지 않는다.

## 2. 프로젝트 정보

- 프로젝트 종류: Python Streamlit 웹 애플리케이션
- 실행 파일: `app.py`
- 물품 생성 화면: `app_pages/05_product_create.py`
- 물품 조회 화면: `app_pages/06_product_select.py`
- 설치 패키지 목록: `requirements.txt`
- 작업 결과 문서: `PRODUCT_UI_REVIEW.md`

물품 API 기본 주소는 다음과 같다.

```python
API_BASE_URL = "https://zero2-mini-project-2.onrender.com"
```

사용할 API는 다음 두 개다.

```text
GET  /product/getall
POST /product/create
```

물품 생성 요청 데이터 형식은 다음과 같다.

```json
{
  "id": 100,
  "name": "무선 키보드",
  "price": 30000
}
```

## 3. 작업 목표

`물품 생성`과 `물품 조회` 두 기능만 개발하고 개선한다.

로그인, 회원가입, 날씨, 서버 체크 등 다른 기능의 동작은 변경하지 않는다.

### 물품 생성

다음 기능이 정상적으로 동작해야 한다.

1. 물품 ID 입력
2. 물품명 입력
3. 가격 입력
4. 입력 예정 내용 미리보기
5. 빈 물품명 검사
6. 0원 이하 가격 검사
7. 서버에 물품 생성 요청
8. 생성 성공 결과 표시
9. 서버 오류 또는 연결 실패 안내
10. 생성 완료 후 물품 조회 화면으로 이동할 수 있는 링크 제공

### 물품 조회

다음 기능이 정상적으로 동작해야 한다.

1. 서버에서 전체 물품 목록 조회
2. 전체 물품 개수 표시
3. 평균 가격 표시
4. 가격 합계 표시
5. 물품명 검색
6. 물품 ID 검색
7. ID 순 정렬
8. 낮은 가격순 정렬
9. 높은 가격순 정렬
10. 이름순 정렬
11. 검색 결과 개수 표시
12. 새로고침 기능
13. 표 형식으로 물품 목록 표시
14. 빈 목록과 서버 오류 안내

## 4. UI 작성 기준

- Streamlit의 기본 컴포넌트를 중심으로 사용한다.
- 화면을 지나치게 화려하게 만들지 않는다.
- 제목, 설명, 입력 영역, 결과 영역의 구분이 명확해야 한다.
- 모든 사용자 안내 문구는 자연스러운 한글로 작성한다.
- 가격에는 천 단위 쉼표와 `원` 단위를 표시한다.
- 버튼 이름만 보고도 동작을 이해할 수 있게 작성한다.
- 모바일 또는 좁은 화면에서도 내용이 심하게 깨지지 않게 구성한다.

## 5. 코드 작성 기준

- 기존 Python 코드 수준을 유지한다.
- 클래스, 디자인 패턴, 비동기 처리 등 불필요하게 어려운 구조를 추가하지 않는다.
- 함수는 한 가지 역할을 중심으로 짧고 명확하게 작성한다.
- 변수명은 의미를 이해할 수 있는 영문 이름을 사용한다.
- 중요한 처리 과정에는 초보자용 한글 주석을 작성한다.
- 코드만 읽어도 입력, 검사, 서버 요청, 결과 표시 순서를 파악할 수 있어야 한다.
- `httpx` 요청에는 반드시 `timeout`을 지정한다.
- 서버 요청은 `try`, `except`로 보호한다.
- 사용자 화면에 긴 영문 오류 메시지나 내부 오류 내용을 그대로 표시하지 않는다.
- 기존 프로젝트에 없는 외부 패키지는 가능하면 추가하지 않는다.

한글 주석은 다음과 같은 수준으로 작성한다.

```python
# 입력한 물품명의 앞뒤 공백을 제거합니다.
clean_name = product_name.strip()

# 서버에 연결하지 못해도 앱 전체가 멈추지 않도록 오류를 처리합니다.
except httpx.RequestError:
    st.error("서버에 연결할 수 없습니다. 잠시 후 다시 시도해 주세요.")
```

## 6. 작업 범위 제한

다음 작업은 별도 요청이 없는 한 하지 않는다.

- 로그인 또는 회원가입 방식 변경
- 인증 정보 변경
- 데이터베이스 구조 변경
- 백엔드 서버 코드 변경
- 물품 수정 기능 추가
- 물품 삭제 기능 추가
- 대규모 파일 구조 변경
- 공통 모듈을 지나치게 세분화하는 리팩터링
- 새로운 프레임워크 도입
- 배포 또는 Git 커밋
- 실제 서버에 테스트 물품 생성

실제 서버 데이터가 변경될 수 있는 테스트는 반드시 먼저 사용자에게 확인한다.

## 7. 작업 순서

1. `README.md`, `requirements.txt`, `app.py`를 확인한다.
2. 물품 생성 및 조회 파일의 현재 코드를 확인한다.
3. 기존 변경 내용을 임의로 삭제하거나 되돌리지 않는다.
4. 두 화면과 관련된 코드만 필요한 범위에서 수정한다.
5. 주요 로직에 한글 주석을 작성한다.
6. Python 문법 검사를 실행한다.
7. 가능하면 Streamlit 앱을 로컬에서 실행해 화면을 확인한다.
8. 조회 기능은 실제 API 응답으로 확인한다.
9. 생성 기능은 서버 데이터를 변경하지 않는 입력 검증까지만 확인한다.
10. 작업 결과를 Markdown 문서에 정리한다.

## 8. 완료 검증 기준

다음 항목을 모두 확인한 후 작업을 완료했다고 보고한다.

- Python 문법 오류가 없다.
- 앱 실행 중 예외 화면이 나타나지 않는다.
- 물품 생성과 물품 조회 메뉴가 한글로 정상 표시된다.
- 생성 화면에서 빈 물품명이 차단된다.
- 생성 화면에서 0원 이하 가격이 차단된다.
- 조회 화면에 서버의 물품 목록이 표시된다.
- 물품명과 ID 검색이 동작한다.
- 네 가지 정렬 방식이 동작한다.
- 서버 연결 실패 시 사용자가 이해할 수 있는 안내가 표시된다.
- 주요 처리 부분에 한글 주석이 있다.
- 다른 화면의 기존 동작을 변경하지 않았다.
- 불필요한 임시 파일이나 테스트 데이터가 남아 있지 않다.

## Codex에 전달할 짧은 요청문

```text

그 지시사항에 따라 물품 생성과 물품 조회 화면만 작업해 줘.

기존 변경 사항은 임의로 되돌리지 말고, 작업 전에 현재 파일 상태를 먼저 확인해 줘.
실제 서버 데이터를 변경하는 테스트는 하지 말고, 필요하면 먼저 나에게 확인해 줘.
작업 후에는 문법 검사와 로컬 화면 검증 결과를 쉬운 한글로 보고해 줘.
```
